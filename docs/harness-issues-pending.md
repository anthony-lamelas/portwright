## Open (add to the Open table)

| Found in | Issue | Idea |
|---|---|---|
| vendoring | `--vendor` only applies on a fresh run. A resumed run loads its saved config and silently ignores new `--vendor` flags, and crates are only copied when `port/.git` doesn't exist | Refuse `--vendor` on a resume whose saved config differs, or vendor on resume before porting starts |
| vendoring | A vendored crate loses its release profile. pc_re's `lto = "fat"` and `codegen-units = 1` live in its own workspace root, which isn't copied, so it runs slower inside a port than its report says | Merge vendored crates' profile settings into the port's workspace root when vendoring |
| vendoring | Clippy (`--all-targets`) and nextest (`--workspace`) lint and test every vendored crate, including its criterion benches, on every gate | Exclude vendored packages from those two steps |
| intake | Several common upstream layouts can't start. `--tests` must be a directory. Upstream tests run with `-c /dev/null` and only the library on `PYTHONPATH`, so helpers like `from common import ...` fail. A license file must be one of the known names (`LICENSE.rst` isn't), and only MIT, BSD and Apache wording is recognised, though cargo-deny allows ISC and Unlicense | Accept a single test file, put the tests folder on `PYTHONPATH`, and widen license names and wordings to what cargo-deny already allows. Found choosing the first vendoring port: tabulate, pyhumps and pytimeparse were ruled out by these alone |
| review | **Python can ship inside a port's wheel.** The integrity scan skips any path with a `target` part, and nothing inspects the built wheel. With `python-source = "target"` in the py crate's `pyproject.toml`, maturin packed `crates/<py>/target/<mod>/__init__.py` (calling `re.escape`) into the wheel and integrity passed, which defeats `--strict-bindings` | Fail if the installed site holds anything but the extension module and its dist-info. Skip only the top-level `target/`. Freeze `pyproject.toml` |
| review | **`--strict-bindings` is a short denylist on one folder.** It doesn't scan a sibling crate that depends on pyo3, or a `#[path]`/`include!` target, and it doesn't flag raw `ffi::PyObject_Format`/`PyOS_double_to_string`, `to_string()`/`format!("{:?}")` on Python objects (which call `str()`/`repr()`), or `floor_div`, `rem`, `divmod`, `getattr_opt`, `get_item` and `PyModule::import` with a variable | Scan every crate that depends on pyo3 and every `#[path]`/`include!` target. Switch to an allowlist of conversion APIs and `ffi::` symbols |
| review | **Some outcome details are never compared.** Exception classes are matched by `__qualname__` only (a homemade `ValueError(Exception)` matches the real one, and `except re.error` would miss pc_re's own class). Exception attributes such as `re.error.pos`, `.pattern` and `.lineno` aren't compared. NaN sign and payload are lost through `float.hex()`. `_ADDRESS` masks any `0x...` token, so `re.compile('0x1f')` equals `re.compile('0xDEAD')` | Compare `__module__` with type, MRO and class. Record `vars(exc)`. Encode floats by their bits. Mask only `at 0x...` |
| review | **Fuzzing runs only once, in harden, but its result counts at the end.** Rust merged in fix review, cleanup, performance and final review is never fuzzed, and those changes can break the frozen fuzz targets without anything noticing. A fix merged in the last harden cycle leaves a stale result either way | Build and briefly re-run the fuzz targets in the report phase, or after each merge outside harden |
| review | **Checks can break or shrink after strengthening.** `_strengthen` ignores the self-comparison result and re-locks the checks as left, so a broken or nondeterministic check sends debuggers chasing it for up to `fix_rounds` sessions. Nothing ensures earlier check files or `regressions.json` entries survive a test-writer stage | Redo the round on a failed self-comparison. Require the new locked files and regressions to include the old ones |
| pc_datetime (review) | **Shim domain leaks.** Any subscriptable is accepted as a tuple (`{0:1,1:0,2:0}` and `b'\x01\x02\x03'` work as dates; long tuples too). `strftime` passes GNU flags and widths (`%-d`, `%#Z`, `%10Y`, `%s`) to glibc, whose version differs between host (2.39) and toolchain image (2.36). `fromtimestamp(1e18)` raises glibc's `strerror` text. A float `utcoffset` is accepted though sub-second offsets are documented as unsupported | Require `type(x) is tuple` with the right length and int fields. Allow only C89/CPython directives with no flags or widths. Map the `OSError` to a fixed error. Include glibc in the version check |
| pc_re, pc_format (review) | **Shim domain leaks.** pc_re doesn't type-check pattern and match arguments: `pattern_split('a,b,,c', ',', 2)` runs `str.split`, and `pattern_groups(<Match>)` returns a bound method compared only by qualname. pc_format accepts sets of str/bytes, whose order follows per-process hash randomization, so the test writer avoided them by hand and that part of the domain is untested | pc_re: require `type(p) is re.Pattern` / `re.Match`. pc_format: refuse sets containing str or bytes |
| review | **Cargo builds in gates still run agent code with network.** `build.rs` files and proc macros run during `maturin build`, `cargo llvm-cov` and the mutation builds, inside the toolchain container but with the host network (to fetch crates) and the workspace mounted read-write | Fetch crates in a first step with network, then build with `--offline` and `--network none` |
| review | **The CLI still requires the host Python to match the image's**, though contained gates now run the original on the image's Python. Kept for now because `PORTWRIGHT_GATES_ON_HOST=1` still runs it on the host | Drop the check (it's in `cli.py`) once host mode is only for tests |
