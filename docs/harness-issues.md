# Harness issues log

Every problem that real runs have exposed in Portwright itself, with the cause and the fix. Port-specific
differences belong in each port's `CONFORMANCE.md`, not here. New entries go at the bottom of the right table.

## Open

| # | Found in | Issue | Idea |
|---|---|---|---|
| A | humanize | The planner rule in #11 is only in the prompt. Code can't tell from a plan whether a task's notes hide unchecked work | Measure Rust coverage of each task's new code with its own checks, at merge time |
| C | pycompat | The harness can't tell a no-op hand-written planted bug from a blind spot in the checks. Both count as "missed" | Before the checks phase, confirm each written bug changes some output, using the upstream tests' inputs |
| D | humanize | If the orchestrator dies by SIGKILL, its containers run until their own time limit (up to about 2 hours) | A heartbeat file the container watches |
| E | humanize | The host-side gate runs (original library, Rust builds) have no memory limit | Run them under a cgroup limit as well |
| F | parse | The final reviewer's findings arrive after the last fix round, so they can only be reported | Allow one more fix round when the final review finds confirmed behavior differences |
| G | pycompat | Warnings aren't compared. `re` emits `FutureWarning` for patterns like `[[:alpha:]]`, and a port that never warns still matches | Record warnings raised during each call as part of the outcome |
| H | pycompat | Two runs at once would each give agents 60% of RAM, so the four pycompat ports run one after another | A machine-wide agent budget shared by all runs |
| I | pc_format | Gaps in a shim's domain surfaced late: `Decimal` arguments in the port phase, attribute lookups after review. Each one cost a debugger round or a restart | Before the checks phase, have a reviewer read the shim and list every way an input can reach behavior outside the built-in it names |
| J | pc_format | #24's fix has a hole. The attribute check gives up on a template Python can't fully parse, but `str.format` evaluates fields before it reaches the parse error, so `'{0.real}{'` still does attribute lookups. The cleanup agent found this when it checked whether `attrs.rs` was reachable | Scan fields lazily up to the parse error in the next pc_format shim, then rerun so the attribute table can go |
| K | pc_unicode | A task merged, then ran again after a restart, costing $0.40 | The merge into main and the board's "merged" status are written separately. Stopping the process between them leaves the task pending | On resume, mark a task merged if its branch is already part of main |
| L | pc_unicode | A benchmark that raises on the original (`lookup('HANGUL SYLLABLE KKWAELH')`, a name that doesn't exist) survived to the performance phase | #30's warning about broken benchmarks reaches the test writer only when the checks need another round. These passed on the first round | When benchmarks are the only problem, give the test writer a short round just for them |
| M | pc_re | `re.DEBUG` (flag 128) prints CPython's internal parse tree and sre bytecode to stdout, and the harness compares stdout. Another domain leak, found after porting started | Approved as a difference for each API that takes flags, with a ruling not to emulate it. The next pc_re shim should refuse `DEBUG` with a fixed error |
| N | pc_re | After a person approves the only difference blocking a task, the task still goes through another agent session before the gate runs again | Re-run the gate on the existing work first, and start an agent only if it still fails |
